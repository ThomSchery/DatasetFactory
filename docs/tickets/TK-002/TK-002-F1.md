# TK-002-F1 — Fixup niezależnego review

## Cel

Usunąć wszystkie sześć findings TK-002 bez rozszerzania funkcji produktu.

## Zakres

1. **Crash-safe reference assets:** transakcja i publikacja pliku muszą mieć
   jawną procedurę recovery. Startup scavenger usuwa stare `.tmp`, finalne pliki
   bez committed DB row oraz DB rows bez finalnego pliku oznacza/naprawia
   deterministycznie. Testuj crash przed/po rename i przed/po commit.
2. **Pełna walidacja obrazu:** reference image musi zostać faktycznie zdekodowany
   (nie tylko nagłówek/IHDR); ucięty PNG, błędny CRC/truncated payload i obraz
   o deklarowanych wymiarach bez danych są odrzucane przed publikacją.
3. **Bounded timeout ffprobe:** po timeoutcie nie ma bezterminowego `communicate()`.
   Kill/terminate/process-tree cleanup ma osobny krótki deadline; po nim zasoby
   są zamykane i zwracany jest stabilny timeout bez wiszącego requestu.
4. **DB-level case-insensitive uniqueness:** nazwa profilu ma unikalność po
   normalizacji/collation na poziomie DB odporną na race (`Foo`/`foo`); konflikt
   integrity mapuje się na stabilne `profile_name_exists`/409.
5. **Walidacja kontenera:** ffprobe metadata musi potwierdzić allowlistę realnego
   formatu/kontenera zgodną z MP4/MKV/MOV; zmiana suffixu AVI→MP4 nie przechodzi.
   Uznane aliasy ffprobe muszą być jawnie zmapowane i testowane.
6. **Trwała kolejność kategorii:** schema przechowuje `ordinal`, zapis zachowuje
   kolejność POST, GET current round-tripuje deterministycznie; migracja ma
   upgrade/downgrade i test danych.

## Done Criteria

- Reprodukcje review stają się testami regresji.
- Startup reconciliation jest idempotentny i nie usuwa committed valid assetów.
- Ucięty 24-byte PNG i błędny payload nie dają 201 ani finalnego pliku.
- Timeout cleanup zawsze kończy się w określonym czasie; brak `communicate(None)`.
- Równoległe `Foo/foo` kończy się jednym profilem i jednym kontrolowanym 409.
- AVI podszyte pod `.mp4` jest odrzucone; prawdziwe MP4/MKV/MOV przechodzą.
- Kolejność kategorii jest stabilna w wielokrotnych runach testów.
- Pełny Ruff/mypy/pytest powtórzony co najmniej 3 razy dla flaky testu; frontend
  typecheck/test/build i `git diff --check` przechodzą.
- Brak zmian w FE tokens/common/design harness i brak nowych globalnych instalacji.
