# TK-001-F1 — Fixup po review Gate 1

## Cel

Usunąć findings review bez rozszerzania zakresu TK-001.

## Zależności

TK-001 oraz implementacja FE-SETUP pozostają nienaruszone.

## Zakres

1. **FFmpeg probe:** `SystemStatusAccess` używa narzędziowo poprawnych argumentów
   (`ffmpeg -version`, `ffprobe -version`, Tesseract `--version`) i testuje
   rzeczywistą semantykę exit code/output; test stuba nie może maskować różnicy.
2. **Redakcja i kontekst logów:** formatter redaguje absolutne ścieżki Windows/
   POSIX oraz jawne pola wrażliwe; obsługuje `request_id`, `run_id`, `stage`,
   `frame_index`; handler 500 loguje wyjątek przez `logger.exception` bez
   ujawniania szczegółów w response.
3. **Granica API:** health router zależy od wąskiego protokołu/use case lub
   bezpośrednio wstrzykniętego `SystemStatusAccess`, nie od konkretnego
   `CompositionRoot`/service locatora.
4. **Invariant bbox:** schema/engine boundary egzekwuje `x+width<=source_width`
   i `y+height<=source_height`; baza ma możliwe CHECK constraints dla
   dodatniej geometrii, a invariant zależny od parenta jest testowany przed
   zapisem w repo/use case. Migracja/test nie może ograniczać się do nazw tabel.
5. **Warning test stack:** jeśli kompatybilna stabilna ścieżka istnieje bez
   łamania locków, usuń warning `httpx`/Starlette; w przeciwnym razie zapisz
   uzasadnione odroczenie, nie zmieniaj na beta/RC.

## Done Criteria

- Health na realnym zainstalowanym FFmpeg/ffprobe raportuje `available=true`.
- Testy rozróżniają `-version` i `--version` oraz failure/timeout/missing.
- Repro z `D:/private/video.mp4` nie pozostawia pełnej ścieżki w logu.
- Log 500 zawiera traceback/korelację po redakcji; response pozostaje bez tracebacku.
- Router nie importuje/nie typuje konkretnego `CompositionRoot`.
- Bbox zerowy/ujemny/poza source nie przechodzi warstwy zapisu; są testy granic.
- Pełny Ruff, mypy, pytest, frontend test/build i `git diff --check` przechodzą.
- Brak zmian w tokenach, common components i design harness.
