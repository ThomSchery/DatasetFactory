Usuń szeroką stałą szynę z podstawowego workspace; zapewnij realny dostęp do wszystkich dotychczasowych destynacji (dashboard, materiały, profile, anotacje, eksporty), np. menu. Zachowaj deep linki. Nie dodawaj martwych przycisków konta/logowania ani atrap.
3. Upload/import oraz Run rozdzielone zgodnie z intencją makiet. Zachowaj realny lokalny import wideo, listę materiałów, wybór źródła, profilu i interwału, walidację, aktywny run, resume/retry/cancel i postęp. Run Setup: wąski panel po lewej i duży obraz po prawej. Pokaż faktyczny obraz wybranego materiału/profilu, bez hardkodowanego gameplay lub liczb z Figmy.
4. Jeden workspace profilu obsługuje nowy i istniejący profil. Search profile filtruje/wybiera profil i wczytuje jego obraz, regiony, klasy i konfigurację OCR; wybrana nazwa jest widoczna. Początek nowego profilu zachowuje tę samą konstrukcję paneli i bazowe grupy znaków, z pustą grupą Custom.
5. Materiałem referencyjnym jest zrzut JPG/PNG. W miejscu obrazu jest czytelna zachęta do dodania zrzutu; obsłuż dotychczasową ścieżkę ręczną do lokalnego obrazu. Notatka wyraźnie usuwa Moment klatki ze ścieżki profilu. Nie zakładaj, że input type=file ujawni pełną ścieżkę Windows; jeśli wybierzesz prawdziwy upload, musi mieć działający bezpieczny backend. Nie usuwaj istniejącego API reference-frame, jeśli inne ścieżki/testy go potrzebują.
6. Rysowanie/wybór/przesuwanie/zmiana wymiarów regionów ma używać sprawdzonego RegionOverlay i odpowiadać obsłudze anotacji. Po narysowaniu boxa fokus trafia w pole nazwy/klasy panelu Annotations; wybór istniejącej klasy lub wpis nowej i Accept zatwierdza szkic. Nowa własna klasa trafia do Custom. Reject odrzuca lokalny szkic. Rozróżnij region OCR i klasę: nie usuwaj istniejącej walidacji charset/PSM ani nie kieruj symbolu klasy game do tessedit_char_whitelist. Custom korzysta z istniejącego modelu klas/ręcznej weryfikacji; nie wdrażaj automatycznego wykrywania ikon/SAM 3.
7. Grupy Custom, Numbers, Letters, Symbols pozostają rozwijalne z wyborem znaków/klas. Zachowaj konfigurację dozwolonych znaków i PSM per region (może być w rozwijanych ustawieniach); stare profile z nullable ustawieniami muszą nadal działać. Lista Annotations odzwierciedla rzeczywistą definicję bieżącego zrzutu, nie wartości przykładowe.

## Trwałość i granice

Nie wolno kasować regionów przez delete/reinsert całej kolekcji: RegionSample.region_id ma CASCADE do próbek/OCR; Annotation.category_id ma RESTRICT. Nie wolno ukryć utraty historii za poprawnym wyglądem nowego profilu. Sprawdź odczyty starych runów, nie tylko liczbę rekordów.

Rozszerz dotychczasowy model/use cases możliwie wąsko. Przed implementacją nadpisywania prześlij rodzicowi krótki konkret: jak zapis zachowa identyfikatory i geometrię/odczyty wcześniejszych runów oraz jak obsłuży usunięcie używanego regionu. Nie wdrażaj dużego systemu rewizji na własną rękę. Możesz równolegle pracować nad wyglądem i frontendowym draftem. Jeśli notatki wymagałyby innej semantyki klas niż istniejące OCR+manual review, wskaż konkretny przypadek rodzicowi zamiast wymyślać nowy pipeline.

Utrzymaj BEGIN IMMEDIATE, kontrolę wersji, normalizację nazw, granice obrazu, własność regionów/klas i atomowy rollback. Save as nie odziedzicza cudzych trwałych ID. Profile przypisane do queued/running/paused/failed/cancelled mają blokadę zmiany definicji, zgodnie z dotychczasowym add_region/update_region_ocr_config. Nie dotykaj żywej bazy użytkownika dla QA.

Poza zakresem: SAM 3, nowy silnik OCR, chmura/login, multiproject storage/folder management tylko na podstawie pustych szablonów, migracja danych operatora bez testów, zmiany w Highlights-AI lub figma-tailwind-tokens.
