# FE-001-F1 — Fundament: klient API, routing i powłoka

Status: WYKONANY

## Cel

Postawić szkielet aplikacji, na którym staną wszystkie ekrany: typowany klient
API, centralne query keys, routing i powłoka nawigacji. Bez ekranów
funkcjonalnych.

## Zależności

FE-SETUP. Backend v1 kompletny (TK-005, TK-007) — kontrakty są stabilne.

## Zakres / poza zakresem

W zakresie: pakiety, `frontend/src/api/**`, `frontend/src/app/**`, powłoka
nawigacji, pięć tras z pustymi widokami, wspólne stany UI, guard szerokości
okna, harness testowy. Poza: jakakolwiek logika ekranów — dashboard, profil,
materiały, weryfikacja, eksport.

## Pliki

- `frontend/package.json` i lockfile
- `frontend/src/api/**` — klient, typy, query keys
- `frontend/src/app/**` — router, powłoka, layout
- `frontend/src/components/common/**` wyłącznie procedurą `new-component.md`
- `frontend/src/test/**` — harness
- `docs/tickets/FE-001/log.md` — Design Plan każdego elementu UI

## Pakiety

React Router, TanStack Query, React Hook Form, Zod. Każdy: stabilna wersja,
oficjalny rejestr, wpis w lockfile, sprawdzona licencja i audit. Bez Zustand,
Tailwind, biblioteki komponentów i frameworka canvas.

## Kontrakt

Jeden typowany klient obejmujący wszystkie endpointy `TECH_PLAN §5`, łącznie
z `POST /frames/{id}/annotations`, `PATCH /annotations/{id}` z opcjonalnym
`bbox`, `decision=reopen` oraz `GET /exports/{id}`. Koperta błędu ma kształt
`{error:{code,message,details,request_id}}` — `details` musi przetrwać do
warstwy UI, bo `bbox_invalid` niesie w nim `annotation_ids`.

## Logika

1. Trasy dokładnie wg FE-04: `/`, `/profiles/new`, `/materials`,
   `/annotations/:runId`, `/exports`. `runId` żyje w URL, nie w stanie.
2. Nawigacja pokazuje pięć destynacji oraz pięć etapów pipeline'u:
   Próbkowanie, Regiony HUD, OCR, SAM 3, Weryfikacja. SAM 3 jest jawnie
   oznaczone jako poza v1, nie udawane.
3. Query keys i invalidacje w jednym module. Żaden komponent nie woła `fetch`
   bezpośrednio i nie implementuje maszyny stanów.
4. Wspólne stany UI wg FE-06: loading, empty, inline error, fatal error,
   progress. Mutacje blokują przycisk i pokazują spinner. Zero optimistic
   update dla danych datasetu.
5. Poniżej 1280 px aplikacja pokazuje komunikat o niewspieranej szerokości,
   nie ściska układu (FE-07).
6. Kody błędów są tłumaczone centralnie na polski komunikat i akcję. Zestaw
   obejmuje `version_conflict`, `review_locked`, `frame_not_reviewable`,
   `bbox_invalid`, `no_annotations`, `active_run`, `export_running`,
   `export_revision_conflict`, `export_source_missing`.

## Done Criteria

- Każdy element UI ma Design Plan w `log.md` i używa katalogu komponentów.
- Klient API pokrywa wszystkie endpointy `§5`, **które backend implementuje**;
  typy odpowiadają kontraktowi. `GET /dashboard` jest wyłączony — nie istnieje
  w backendzie i realizuje go TK-008. Klient nie zawiera spekulacyjnego typu dla
  endpointu, którego nikt nie widział.
- Test dowodzi, że `details` z koperty błędu dociera nienaruszone do warstwy UI.
- Pięć tras renderuje się z jawnym empty state; nawigacja działa klawiaturą.
- Test guardu szerokości okna: poniżej 1280 px komunikat, powyżej normalny układ.
- Żaden komponent React nie woła `fetch` ani nie trzyma statusu runu u siebie.
- Vitest, typecheck i build zielone; audit bez ostrzeżeń.
