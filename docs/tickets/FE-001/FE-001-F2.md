# FE-001-F2 — Materiały, uruchomienie runu i dashboard

Status: GOTOWY

## Cel

Dać użytkownikowi drogę od pliku wideo do uruchomionego i obserwowanego runu.

## Zależności

FE-001-F1 oraz TK-008 — `GET /dashboard` nie istniał w backendzie do 2026-08-05
i bez niego ekran dashboardu nie ma źródła danych.

## Zakres / poza zakresem

W zakresie: ekran materiałów, tworzenie i sterowanie runem, dashboard ze stanem
systemu i progresem pipeline'u. Poza: tworzenie profilu (F3), weryfikacja (F4),
eksport (F5).

## Pliki

- `frontend/src/features/materials/**`
- `frontend/src/features/dashboard/**`
- `docs/tickets/FE-001/log.md`

## Kontrakt

`POST /materials`, `GET /materials`, `POST /runs`, `POST /runs/{id}/{start,
pause,resume,cancel}`, `GET /runs/{id}`, `GET /dashboard`, `GET /health`.
Mutacje sterujące runem wymagają `expected_version`.

## Logika

1. Materiał: lokalna ścieżka pliku, wybór profilu, interwał próbkowania.
   Walidacja inline przez Zod, a wynik walidacji backendu pokazany bez
   tłumaczenia kodu błędu na własną interpretację.
2. Uruchomienie runu prowadzi na `/annotations/:runId`, bo `runId` żyje w URL.
3. Polling co 2 s wyłącznie w statusach nonterminal; w `review_ready`,
   `completed`, `failed` i `cancelled` polling milknie.
4. Progres pokazuje etap bieżący, liczbę klatek ukończonych i całkowitą oraz
   stabilny `error_code`, gdy run padnie.
5. Gdy aktywny OCR ma `experimental=true` albo `quality_gate != passed`, ekran
   pokazuje stałe ostrzeżenie i nie sugeruje, że anotacje są poprawne. Dziś
   Tesseract zawsze spełnia ten warunek, więc ostrzeżenie jest widoczne zawsze.
6. Dashboard pokazuje aktywny projekt i run, liczby klatek per status oraz stan
   FFmpeg, Tesseract, workspace i GPU. SAM 3 jako „poza v1".
7. `409 active_run` pojawia się przy **starcie lub wznowieniu** drugiego runu,
   nie przy jego utworzeniu — `POST /runs` kończy się sukcesem i zostawia run
   w `queued`. Konflikt jest komunikatem, nie awarią.
8. Wybór profilu operuje na `GET /profiles/current`. v1 ma jeden profil naraz,
   bo lista i edycja profili (F02) są poza zakresem; kontrolka wyboru zostaje,
   żeby rozszerzenie nie wymagało przebudowy formularza.

## Done Criteria

- Design Plan w `log.md` dla każdego elementu UI.
- Test interakcji: import materiału, utworzenie runu, start, przejście pollingu
  ze statusu nonterminal do terminalnego i zatrzymanie odpytywania.
- Test `409 active_run` oraz konfliktu `expected_version` na pause/resume/cancel.
- Ostrzeżenie o `experimental`/`quality_gate` jest widoczne i nie da się go
  ukryć przypadkiem — test to przypina.
- Każdy widok ma loading, empty, error i success.
- Vitest, typecheck i build zielone.
