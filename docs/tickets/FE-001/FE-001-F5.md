# FE-001-F5 — Eksport i bramki Gate 3 UI

Status: GOTOWY

## Cel

Domknąć pionowy przepływ ekranem eksportu i przejść bramki jakości całego
interfejsu.

## Zależności

FE-001-F1 … FE-001-F4 oraz TK-009 — zamknięcie runu po eksporcie wymaga
endpointu, którego dziś nie ma. Bramki wymagają wszystkich ekranów, więc ten
ticket jest ostatni.

## Zakres / poza zakresem

W zakresie: ekran eksportu, screenshot QA, dostępność, kontrast, uzupełnienie
TD-007/010/013. Poza: train/val, YOLO, eksport przyrostowy — nie obiecujemy ich
nawet w tekstach interfejsu.

## Pliki

- `frontend/src/features/exports/**`

- `docs/TECH_DEBT.md` — kolumna „Gdzie" dla TD-007, TD-010, TD-013

## Kontrakt

`POST /exports`, `GET /exports/{id}`. Odpowiedź niesie status, `input_revision`,
`error_code`, manifest i relatywną ścieżkę wyniku.

## Logika

1. Eksport startuje na żądanie i jest odpytywany do stanu terminalnego.
2. Manifest pokazuje `annotation_sources` — ile anotacji pochodzi z OCR, a ile
   z ręki. To licznik pochodzenia, nie trafności OCR, i tekst interfejsu nie
   może sugerować inaczej.
3. Stabilne kody błędów mają własne komunikaty: `400 no_accepted_frames`,
   `409 export_running`, `export_revision_conflict`, `export_source_missing`,
   `export_process_interrupted`.
4. Ukończony eksport jest niezmienny. Jeśli użytkownik później otworzy klatkę
   ponownie i ją zmieni, interfejs mówi wprost, że nowy stan wymaga nowego
   eksportu, i nie sugeruje aktualizacji istniejącego.
5. Po ukończonym eksporcie użytkownik może zamknąć run (`POST /runs/{id}/complete`
   z TK-009). To jawna decyzja, nie automat — granica „ten materiał jest
   przerobiony”. Run bez ukończonego eksportu nie daje się zamknąć.
5. Ścieżka wyniku jest relatywna względem workspace; interfejs nigdy nie
   pokazuje ścieżek absolutnych ani nie pozwala ich podać.

## Done Criteria — Gate 3 UI

- Design Plan w `log.md` dla każdego elementu UI; katalog komponentów aktualny.
- Tokeny i kompozycja wierne baseline'owi Impeccable; teksty polskie, terminy
  OCR, SAM i HUD bez tłumaczenia.
- Screenshot QA przy 1440 px dla pięciu tras oraz stanów loading, empty i error.
- Zero nierozwiązanych zmiennych CSS, brak poziomego przewijania powyżej
  1280 px, brak pobierania fontów z zewnątrz.
- Klawiatura, focus, semantyka i kontrast działają na wszystkich ekranach.
- Jeden test Playwright pionowego przepływu na fixture wideo i stubie OCR.
- TD-007, TD-010 i TD-013 mają uzupełnione lokalizacje.
- Vitest, typecheck, build i audit zielone.

## Ryzyko

Playwright pobiera własne binarki przeglądarek — to pierwsza w tym projekcie
zależność spoza rejestru npm. Jeśli pobranie jest zablokowane, screenshot QA
staje na tej bramce. Dlatego ten ticket jest ostatni i nie blokuje czterech
pozostałych.
