# TK-002 — Profil gry i import lokalnego materiału

## Cel

Dostarczyć pierwszy trwały fragment domeny: utworzenie jednego profilu gry z
referencją, regionami i klasami oraz rejestrację lokalnego wideo po walidacji.

## Zależności

TK-001.

## Zakres / poza zakresem

W zakresie: `DatasetDefinitionEngine`, modele/repozytoria profilu i materiału,
opaque serving obrazu referencyjnego, endpointy profilu/materials, ffprobe metadata.
Poza: edycja/lista profili F02, sampling klatek, OCR, upload plików.

## Pliki

- `backend/app/engines/definition/**`
- `backend/app/managers/workflow/profile_use_cases.py`, `material_use_cases.py`
- `backend/app/access/media/probe.py`
- `backend/app/access/store/{models,repositories}/**`
- `backend/app/api/{profiles,materials,assets}.py`
- migracja Alembic ticketu i testy odpowiadających modułów

Wszystkie ścieżki są pod `D:\my\Projects\DatasetFactory\`.

## Pakiety

Istniejące z TK-001; FFmpeg/ffprobe wywoływane jako skonfigurowany subprocess.
Bez nowych bibliotek do uploadu lub file pickera.

## Kontrakt

Implementuje `POST /profiles`, `GET /profiles/current`, `POST /materials`,
`GET /materials` oraz bezpieczny endpoint opaque reference asset dokładnie wg
`TECH_PLAN §5`. Request profilu zawiera cały agregat i zapisuje go atomowo.

## Logika

1. Backend waliduje absolutną ścieżkę referencji, odczytuje obraz i kopiuje go
   atomowo do workspace.
2. Engine waliduje unikalne nazwy, dodatnie bbox w granicach source i kategorie.
3. Repo zapisuje profil/regiony/kategorie w jednej transakcji.
4. Import wideo sprawdza plik, allowlist rozszerzeń, 50 GB, 2 h, metadane i dysk;
   przechowuje fingerprint size+mtime, nie kopiuje źródła.
5. Lista materiałów jest stronicowana; API nie zwraca pełnej ścieżki źródłowej,
   tylko basename oraz status dostępności.

## Done Criteria

- Unit tests engine: bbox na krawędzi, poza obrazem, zero/negative, duplikaty klas.
- Integracja: atomowy zapis profilu; failure kopiowania/transakcji nie zostawia
  osieroconego aktywnego rekordu/assetu.
- ffprobe ma timeout 30 s i zabicie process tree; błędy mapują się na stabilne codes.
- Materiały >50 GB/>2 h/unsupported/missing/mało dysku są odrzucane przed runem.
- Endpoint asset przyjmuje tylko UUID/relpath z bazy; test path traversal przechodzi.
- Pydantic i backend engine walidują niezależnie; router nie zawiera reguł domeny.
- Migracja up/down/up i wszystkie gate'y TK-001 pozostają zielone.
- TD-001/002/009 mają uzupełnione lokalizacje implementacji.
