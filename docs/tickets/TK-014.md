# TK-014 — Silnik OCR: status i komunikaty nie znają Tesseracta

Status: WYKONANY (2026-11-26)

## Cel

Oś zmienności „silnik OCR” (PRAG-08, system zewnętrzny → adapter) ma być
odizolowana na tyle, żeby wymiana silnika nie wymagała ruszania statusu
systemu, Managera ani ekranów.

## Powód

Przegląd zmienności z 2026-11-26. `access/status/service.py` importował
`TesseractRuntimeIdentity` i zawierał `TesseractDependencyProbe`, pole `tesseract`
szło przez snapshot, `/health` i UI, a Manager wybierał tekst ostrzeżenia po
`engine_id == "tesseract"`.

## Zakres / poza zakresem

W zakresie: sonda zależności należy do adaptera (`access/ocr/tesseract_probe.py`),
status zna tylko kontrakt `OcrDependencyProbe`; pole `tesseract` → `ocr` z nazwą
silnika; ostrzeżenie o bramce jakości nazywa silnik z provenance; ekran „OCR
engine” nie zakłada Tesseracta.

Poza zakresem: wybór silnika, ustawienia `DF_TESSERACT_*` (konfiguracja adaptera),
treść komunikatów błędów `ocr_provenance_*` (patrz TD-023).

- [x] `/health` i `/dashboard` niosą `ocr` z polem `engine`.
