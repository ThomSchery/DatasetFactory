# TK-004 — Trwały workflow, checkpointy i odzyskiwanie

## Cel

Zintegrować profil, materiał, sampling i OCR w jeden trwały run, który raportuje
progres, respektuje jeden aktywny job i po restarcie wznawia się bez duplikatów.

## Zależności

TK-003-F1 z pozytywnym technicznym Gate 2. Jakościowy Gate Tesseract pozostaje
`failed`, jawnie zaakceptowany jako TD-014; nie blokuje budowy workflow.

## Zakres / poza zakresem

W zakresie: `DatasetWorkflow`, worker max_workers=1, run/frame/sample/observation/
checkpoint persistence, lifecycle i polling API, pause/resume/cancel/recovery.
Poza: review mutations, COCO, SSE/WebSocket, wielu równoległych workerów.

## Pliki

- `backend/app/managers/workflow/{manager,worker,recovery,state_machine}.py`
- `backend/app/access/store/repositories/{runs,frames,checkpoints}.py`
- `backend/app/api/runs.py`
- migracja i testy jednostkowe/integracyjne modułu

## Pakiety

Standard library concurrency/asyncio plus istniejący stack. Bez Celery, Redis,
brokera i bez nowego scheduler frameworka.

## Kontrakt

Implementuje `/runs`, `/runs/{id}/{start,pause,resume,cancel}`, status runu i
stronicowane frames z `TECH_PLAN §5`. Mutacje wymagają `expected_version`.

## Logika

1. State machine egzekwuje wyłącznie statusy/przejścia z `CONTEXT`/`CORE_FLOWS`.
2. Start w transakcji rezerwuje globalny slot; drugi run dostaje `409 active_run`.
3. Worker dla każdej klatki sprawdza checkpoint+hash, wykonuje brakujący etap,
   atomowo publikuje artefakt i dopiero wtedy commituje status.
4. Heartbeat co ≤5 s/etap. Startup wykrywa osierocony run, weryfikuje artefakty,
   ustawia `paused`; resume zaczyna od pierwszego brakującego etapu.
5. Każda observation/checkpoint zapisuje pełne `OcrProvenance`, w tym
   `quality_gate` i `experimental`; run API ujawnia ostrzeżenie dla Tesseract.
6. Pause kończy bezpieczny etap; cancel sygnalizuje/zabija subprocess i zachowuje
   checkpoint. Błąd infrastruktury ustawia stable `error_code` i `failed`.
7. Po ostatnim OCR run ma `review_ready`; brak odczytów nie jest awarią.

## Done Criteria

- Test tabeli wszystkich dozwolonych i zakazanych przejść run/frame.
- Test jednego aktywnego runu przy dwóch równoczesnych requestach.
- Test crash window: artefakt bez commita, commit bez/ze złym hashem, restart w
  każdym etapie; wznowienie nie duplikuje frames/observations.
- Idempotency unique `(run_id,frame_index,stage)` i rollback zależnych draftów
  tylko dla uszkodzonej klatki.
- Źródło zmienione/zniknięte po imporcie daje kontrolowany status bez kasowania danych.
- API polling zwraca total/completed/current stage/error/version; listy ≤100.
- API zwraca `ocr_engine`, `experimental=true`, `quality_gate=failed` i user-facing
  warning; status nigdy nie jest domyślnie ukrywany.
- Worker nie trzyma transakcji podczas subprocess; clean shutdown nie startuje
  nowej klatki i maksymalnie pauzuje aktywną.
- Composition root smoke, lint/typecheck/test i realny fixture Gate 2 pozostają zielone.
- TD-003/008/009 uzupełnione; marker @SCALE przy implementacji worker/polling.
