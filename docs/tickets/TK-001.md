# TK-001 — Fundament aplikacji i trwały workspace

## Cel

Utworzyć uruchamialny szkielet FastAPI/React, composition root, konfigurację na
`D:`, bazę SQLite z pierwszą migracją oraz jawny health/status. Po ticketcie nie
ma jeszcze funkcji datasetu, ale pełny graf aplikacji buduje się i jest testowany.

Alembic, workspace confinement, logi JSONL, `/api/v1/health`, composition root,
minimalny Vite proxy/build shell. Poza: profile, media, worker, OCR, docelowy UI.

## Pakiety

FastAPI, Uvicorn, Pydantic Settings, SQLAlchemy 2, Alembic, pytest, httpx,
ruff/mypy; React/Vite/TypeScript tylko jako kompilowalny shell. Przed dodaniem
sprawdzić stabilną wersję i podatności w oficjalnym registry; lockfile obowiązkowy.

## Kontrakt

`GET /api/v1/health` zwraca `200` z wersją oraz statusem DB/workspace/FFmpeg/
Tesseract/GPU; `503` tylko gdy DB lub workspace uniemożliwia działanie. Error
envelope oraz `request_id` dokładnie jak w `TECH_PLAN §5`.

## Logika

1. Załaduj config z env; odrzuć host inny niż loopback i katalog bez zapisu.
2. Utwórz kontrolowane katalogi workspace oraz rotujący log JSONL.
3. Uruchom `alembic upgrade head`, następnie zbuduj repozytoria i status access.
4. Zbuduj pełny composition root; zasoby są wstrzykiwane, nie tworzone w routerach.
5. Health sprawdza zależności bez uruchamiania runu.
6. Vite dev proxy prowadzi `/api` do loopback; packaged build może być serwowany
   przez FastAPI, ale finalna komenda powstaje w TK-006.

## Done Criteria

- `.venv`, pip cache, node_modules i workspace są na `D:`; repo nie instaluje globalnie.
- Pierwsza migracja tworzy tabele z `TECH_PLAN §3`, ma `upgrade` i `downgrade`.
- SQLite ma foreign keys ON i WAL; relpath nie może wyjść poza workspace.
- Każdy request ma `request_id`; log nie ujawnia pełnej ścieżki/cropu/OCR.
- Routery mają Pydantic `extra=forbid` i jawny komentarz/politykę `local-public`.
- Smoke test buduje PEŁNY composition root z temp SQLite i atrapami systemowych
  zasobów bez uruchamiania serwera (gate DI/composition wymagany od pierwszego modułu).
- Testy: migracja up/down/up, config rejection, path traversal, health 200/503,
  error envelope; backend lint/typecheck/test i frontend typecheck/build przechodzą.
- `docs/TECH_DEBT.md` kolumna „Gdzie” jest uzupełniona dla dotkniętych TD.
