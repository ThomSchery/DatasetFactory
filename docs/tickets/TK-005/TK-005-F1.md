## Kontrakt

Implementuje `GET /frames/{id}`, `GET /frames/{id}/image`, `PATCH /annotations/{id}`,
`DELETE /annotations/{id}` i `POST /frames/{id}/review` z `TECH_PLAN §5`. Wszystkie
mutacje wymagają `expected_version`.

## Logika

1. Engine przyjmuje immutable snapshot klatki i zbiór dozwolonych kategorii
   profilu; nie zna DB, HTTP ani filesystemu. Klasa spoza profilu to `400`.
2. Usunięcie ustawia `status='deleted'`, zachowuje `observation_id` i wiersz
   `ocr_observations`; provenance OCR nigdy nie znika.
3. Accept wymaga co najmniej jednej aktywnej anotacji (`400 no_annotations`);
   reject wyklucza całą klatkę. Klatka `accepted` jest zablokowana przed dalszą
   mutacją (`409 review_locked`); ponowne otwarcie jest poza v1.
4. Migracja `0005` dodaje `pipeline_runs.review_revision` (default `0`),
   `exports.error_code` oraz partial `UNIQUE(run_id) WHERE status IN
   ('queued','running')` na `exports`.
5. Każda mutacja review inkrementuje w jednej transakcji `version` swojego
   agregatu oraz `review_revision` runu. Etapy workera `review_revision` nie
   dotykają.
6. Recovery nie tyka klatek z `review_status != 'pending'`: plan rekoncyliacji
   pomija je, nie kasuje anotacji i nie zeruje decyzji. Pominięcia są zliczane
   w `RecoveryResult` i wystawiane jako ostrzeżenie w statusie runu. Realizuje
   wprost CF-04 („nigdy zaakceptowane wcześniejsze klatki”).
7. `GET /frames/{id}/image` serwuje wyłącznie relpath z bazy, po `resolve()`
   pod workspace, z właściwym content type; nigdy dowolną ścieżkę.

## Done Criteria

- Property/unit testy przejść review i walidacji bbox w engine, bez DB i HTTP.
- Konflikt `expected_version` zwraca `409`; równoległa mutacja nie gubi
   inkrementu `review_revision`.
- Nie można przypisać klasy innego profilu ani mutować klatki `accepted`.
- Test przypina, że `commit_ocr` na klatce `review_pending` kończy się
   `InvalidTransitionError` przed jakimkolwiek kasowaniem anotacji.
- Test recovery: uszkodzony artefakt OCR klatki `accepted` i `rejected` nie
   kasuje anotacji, nie zmienia `review_status`, nie zmienia `review_revision`
   i zwraca zliczone pominięcie; ta sama rekoncyliacja jest idempotentna.
- Test path confinement i content type dla `/frames/{id}/image`.
- Migracja `0005` przechodzi forward na jednorazowej bazie, `schema validate`
   zielone, chain migracji spójny z testowym registry.
- `test_composition` i `test_api_boundaries` zielone dla nowych modułów;
   engine review nie importuje SQLAlchemy ani FastAPI.
- Pełny lint/typecheck/test backendu zielony; TD-005 uzupełniony o `plik:linia`.
