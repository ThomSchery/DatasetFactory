## Zakres

1. **Backend** — `DELETE /api/v1/runs/{run_id}?expected_version=N` → `204`.
   - Jedna transakcja `BEGIN IMMEDIATE`: run istnieje (`404 run_not_found`), wersja się zgadza (`409 version_conflict`), run nie przetwarza klatek — status `running` albo zajęty slot / rezerwacja wznowienia (`409 run_in_progress`), żaden eksport runu nie jest `queued`/`running` (`409 export_running`). Potem `DELETE pipeline_runs` — klatki, próbki regionów, obserwacje OCR, anotacje, checkpointy i rekordy eksportów schodzą kaskadą FK (`PRAGMA foreign_keys=ON`).
   - Po commicie pliki: `workspace/runs/<run_id>/` (klatki, wycinki regionów, checkpointy) i `workspace/exports/<export_id>` każdego eksportu runu. Najlepszy wysiłek z krótkim ponowieniem (Windows trzyma uchwyt obrazu chwilę po odczycie).
   - Start: sprzątanie sierot — katalog `runs/<uuid>` bez wiersza `pipeline_runs` i wpis `exports/<uuid>` bez wiersza `exports` (zostają po nieudanym usunięciu pliku). Tylko nazwy-UUID; inne wpisy nietknięte.
   - `GET /runs` — podsumowanie dostaje `version` (potrzebne do `expected_version`).
   - Materiał wideo i profil zostają. Usunięcie runu `paused`/`failed`/`cancelled` zwalnia blokadę edycji profilu (`BLOCKING_RUN_STATUSES`) i miejsce aktywnego runu na dashboardzie.
2. **Frontend** — lista „Runs to review”: przycisk „Delete” w wierszu runu (obok „Open review”), wyłączony dla `running`; okno potwierdzenia (`Dialog`) z nazwą profilu, id runu i liczbą klatek; błąd w oknie (`describeApiError`); po sukcesie odświeżenie `runs`, `dashboard`, `exports`; gdy strona listy opustoszeje, cofnięcie o stronę.
3. **Kontrakt** — wiersz `DELETE /runs/{id}` i opis w `docs/TECH_PLAN.md`; kod `run_in_progress` w `messages.ts`; akcja `export_running` ogólna („Wait for it to finish, then try again.”).
