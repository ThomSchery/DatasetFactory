# TK-009 — Zamknięcie runu po eksporcie

Status: GOTOWY

## Cel

Nadać sens statusowi `completed`: dać sposób na jawne zamknięcie runu, którego
materiał został przerobiony i wyeksportowany.

## Powód

Luka wykryta podczas FE-001-F2. `RUN_TRANSITIONS` dopuszcza `review_ready →
completed`, ale żaden endpoint w `TECH_PLAN §5` tego przejścia nie wykonuje.
Run zostaje w `review_ready` na zawsze, a `completed` jest stanem martwym —
audyt w TK-006 porównuje funkcje z rzeczywistością i i tak by to wychwycił.

Run w `review_ready` nie blokuje kolejnego (slot jest zwalniany przy przejściu
z `running`), więc to nie jest błąd blokujący pracę — tylko brak granicy
„ten materiał jest przerobiony”.

## Zależności

TK-005, TK-008. Musi być gotowy przed FE-001-F5, gdzie powstaje ekran eksportu.

## Zakres / poza zakresem

W zakresie: endpoint zamykający run, reguła kiedy wolno go zamknąć, kontrakt
w `§5` i testy. Poza: automatyczne zamykanie, archiwizacja runu, historia
runów (TD-007), zmiany w samym eksporcie.

## Pliki

- `backend/app/api/runs.py`
- `backend/app/managers/workflow/manager.py` i `access/store/repositories/runs.py`
- `docs/TECH_PLAN.md` §5 oraz `docs/CORE_FLOWS.md` CF-06
- testy

## Pakiety

Bez nowych zależności. Bez migracji — `completed` istnieje w schemacie.

## Kontrakt

`POST /runs/{id}/complete` z `{expected_version}` → `202`. Błędy:
`409 invalid_transition` poza `review_ready`, `409 version`, `404`.

## Logika

1. Przejście dozwolone wyłącznie z `review_ready`, zgodnie z `RUN_TRANSITIONS`.
   Nie dodajemy nowych krawędzi do maszyny stanów.
2. Zamknięcie wymaga co najmniej jednego ukończonego eksportu tego runu.
   Zamykanie runu, z którego nic nie wyszło, ukrywałoby niedokończoną pracę —
   a to jedyna granica, jaką ten status wyznacza.
3. Operacja jest idempotentna wobec `expected_version` jak pozostałe mutacje
   runu i nie dotyka klatek, anotacji ani `review_revision`.
4. Zamknięty run pozostaje widoczny i czytelny; `completed` jest terminalne, więc
   nie wraca do `running`. Klatki i eksporty zostają nienaruszone.
5. Dashboard przestaje pokazywać taki run jako aktywny — to wynika wprost
   z istniejącego `NONTERMINAL_RUN_STATUSES`, bez zmian w TK-008.

## Done Criteria

- Test przejścia: `review_ready → completed` przechodzi, każdy inny status daje
  `409 invalid_transition`.
- Test braku eksportu: run bez ukończonego eksportu nie daje się zamknąć.
- Test `expected_version`: konflikt daje `409`.
- Test, że zamknięcie nie zmienia klatek, anotacji ani `review_revision`.
- Test, że dashboard przestaje raportować run jako aktywny po zamknięciu.
- `TECH_PLAN §5` i CF-06 opisują operację; `test_api_boundaries` i
  `test_composition` zielone.
- Pełne bramki backendu zielone: ruff, mypy strict, cały pytest.
