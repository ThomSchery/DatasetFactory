# TK-006 — E2E, hardening i uruchomienie jedną komendą

## Cel

Zamknąć MVP powtarzalnym uruchomieniem, pełną weryfikacją pionowego przepływu,
testem restartu oraz pakietem diagnostycznym — bez wdrożenia chmurowego.

## Zależności

TK-001…TK-005, FE-SETUP, FE-001.

## Zakres / poza zakresem

W zakresie: PowerShell scripts na D:, fixture E2E, Playwright, packaged-local SPA,
gates jakości, dokumentacja uruchomienia/Tesseract, audit granic i długu.
Poza: installer Windows, podpis binarny, CI, chmura, monitoring zewnętrzny.

## Pliki

- `scripts/{bootstrap,dev,check,package-local}.ps1`
- `README.md`, `docs/RUNBOOK.md`
- `frontend/e2e/**`, końcowe fixtures backendu
- korekty testów/konfiguracji wszystkich modułów bez rozszerzania funkcji

## Pakiety

Playwright jako dev dependency; cache przeglądarki jawnie na `D:`. Bez generatora
installera. Żadna komenda nie instaluje globalnie ani nie zmienia systemowego PATH.

## Kontrakt

- `scripts/bootstrap.ps1`: tworzy `.venv` na D, instaluje lockowane zależności,
  sprawdza Tesseract/FFmpeg i podaje instrukcję, ale nie instaluje systemowo.
- `scripts/dev.ps1`: jedna komenda uruchamia backend+Vite i sprząta procesy po Ctrl+C.
- `scripts/check.ps1`: format/lint/typecheck/test/build/Playwright/gates.
- `scripts/package-local.ps1`: buduje SPA obsługiwane przez FastAPI; nie tworzy chmury.

## Logika

1. E2E używa krótkiego legalnego fixture wideo i deterministic `OcrEngine` stub;
   osobny test integracyjny uruchamia realny Tesseract, jeśli dependency jest dostępne.
2. Scenariusz: health → profile → material → run → wymuszony restart → resume →
   review correction/delete/accept/reject → export → walidacja COCO.
3. Drugi scenariusz sprawdza brak dysku/source missing/409 active run w kontrolowany sposób.
4. Finalny audit porównuje F01/F03–08/F11–16 z testami i artefaktami; brak funkcji
   F02/F09/F10 jest widoczny, nie zasymulowany mockiem w produkcji.

## Done Criteria — Gate 4

- Nowy checkout na D uruchamia bootstrap/dev według README bez zgadywania ścieżek.
- Tesseract missing daje instrukcję dev-only na D, nie traceback; FFmpeg już
  zainstalowany jest wykrywany bez ponownej instalacji.
- Packaged-local nie może dołączać obecnej nieweryfikowalnej binarki Tesseract;
  albo używa weryfikowalnego runtime, albo jawnie działa bez realnego OCR z
  diagnostyką TD-015.
- Pełny E2E przechodzi, w tym kill/restart backendu i brak duplikatów po resume.
- Eksport otwiera validator COCO i zawiera wyłącznie accepted frames/annotations.
- `check.ps1` przechodzi: ruff/format/mypy/pytest, lint/typecheck/Vitest/build,
  Playwright, composition-root smoke i architecture import tests.
- Screenshoty 1440 px zweryfikowane wizualnie; baseline i pięć tras bez regresji.
- Dependency audit/licencje zapisane; brak beta/RC i znanych wysokich podatności.
- Wszystkie TD-001…013 mają realne `plik:linia` albo jawne „nie zaimplementowano”;
  nowe uproszczenie wymaga dopisania ledgeru przed zamknięciem.
- `git status` nie zawiera cache/modeli/workspace/bazy/logów; `.gitignore` je obejmuje.
- Class responsibility gate: każda nowa klasa ma jedną odpowiedzialność, wąskie
  API; nie powstał nowy God Object w `DatasetWorkflow` ani adapterach.
- AI/ML boundary gate: OCR input/provider/parser/validation/persistence są rozdzielone;
  timeout/retry/provenance/fallback mają testy; brak swobodnego shell string/path.
- Brak CI jest nadal jawnym TD-012; trigger pierwszego współpracownika opisany.
