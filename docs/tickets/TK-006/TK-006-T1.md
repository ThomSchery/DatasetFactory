# TK-006-T1 — Skrypty uruchomieniowe, jedna bramka i dokumentacja

Status: WYKONANY

## Cel

Sprowadzić uruchomienie i weryfikację projektu do czterech komend, żeby nowy
checkout na `D:` startował według README bez zgadywania ścieżek, a każda bramka
jakości szła przez jedno wywołanie zamiast siedmiu komend z pamięci.

## Zależności

FE-001 (wykonany, Gate 3 domknięty). Idzie pierwszy z T1–T4, bo `check.ps1`
staje się bramką, przez którą przechodzą T2, T3 i T4.

## Zakres / poza zakresem

W zakresie: `scripts/bootstrap.ps1`, `scripts/dev.ps1`, `scripts/check.ps1`,
`README.md`, `docs/RUNBOOK.md`. Skrypty wyłącznie orkiestrują istniejące
komendy — nie zmieniają treści żadnej bramki ani konfiguracji narzędzi.

Poza zakresem: `package-local.ps1` (T4), CI (TD-012), installer, podpis binarny,
nowe testy funkcjonalne, zmiana zawartości istniejących bramek, instalowanie
czegokolwiek systemowo lub modyfikacja systemowego `PATH`.

## Pliki

- `scripts/{bootstrap,dev,check}.ps1`
- `README.md`, `docs/RUNBOOK.md`
- `.env.example` — wyłącznie jeśli bootstrap ujawni brakujący klucz

## Kontrakt

`scripts/bootstrap.ps1`

- tworzy `.venv` i instaluje zależności z `uv.lock` — wersje lockowane, bez
  rozluźniania pinów;
- sprawdza FFmpeg/ffprobe i Tesseracta pod ścieżkami z `.env`, weryfikując
  `DF_TESSERACT_RUNTIME_SHA256` i `DF_TESSERACT_MODEL_SHA256`;
- brak zależności kończy się instrukcją dev-only wskazującą katalog na `D:`,
  nigdy tracebackiem;
- już zainstalowany FFmpeg jest wykrywany i nie jest instalowany ponownie;
- nic nie instaluje globalnie i nie zmienia systemowego `PATH`.

`scripts/dev.ps1`

- jedna komenda podnosi backend (`uvicorn`) i Vite;
- `Ctrl+C` sprząta oba procesy, nie zostawia osieroconego portu 8000 ani 5173.

`scripts/check.ps1` uruchamia w tej kolejności i przerywa na pierwszej
czerwonej bramce, wypisując na końcu czytelne podsumowanie:

| Warstwa | Komenda |
| --- | --- |
| backend format | `ruff format --check` |
| backend lint | `ruff check` |
| backend typy | `python -m mypy` |
| backend testy | `pytest` |
| frontend typy | `npm run typecheck` |
| frontend testy | `npm test` |
| frontend build | `npm run build` |
| E2E | `npm run e2e` |
| E2E root safety | `npm run test:e2e-root` |

`npm run test:e2e-root` jest wymieniony jawnie, bo dziś nie wchodzi ani w
`npm test`, ani w `npm run e2e` — to była realna luka wykryta przy domykaniu
Gate 3. Composition-root smoke i architecture import tests są już częścią
`pytest` i `npm test`; nie duplikuj ich osobnym wywołaniem.

## Logika

1. Skrypty są PowerShell i zakładają layout na `D:` zgodny z `.env.example`.
   Ścieżki pochodzą z konfiguracji, nie z literałów rozsianych po skryptach.
2. README opisuje drogę od pustego checkoutu: wymagania, kopiowanie
   `.env.example`, bootstrap, dev, check. RUNBOOK opisuje pracę codzienną:
   gdzie leżą workspace, cache, baza i logi, jak wyczyścić stan, co zrobić gdy
   brakuje Tesseracta lub FFmpega.
3. `check.ps1` musi być idempotentny: dwa przebiegi bez zmiany kodu zostawiają
   `git status` czysty. Visual QA nadpisuje śledzone PNG, więc drugi przebieg
   ma dać identyczne hashe — mechanizm determinizmu jest już w repo od FIX4.

## Done Criteria

- Nowy checkout na `D:` przechodzi bootstrap → dev według samego README, bez
  zgadywania ścieżek i bez wiedzy spoza dokumentu.
- Brak Tesseracta daje instrukcję, nie traceback; obecny FFmpeg jest wykryty
  bez ponownej instalacji; niezgodna suma SHA-256 zatrzymuje bootstrap.
- `dev.ps1` podnosi oba procesy jedną komendą i sprząta je po `Ctrl+C`.
- `check.ps1` przechodzi w całości na czystym `main`, a wymuszona czerwona
  bramka zatrzymuje go z czytelnym komunikatem, nie ciszą.
- Dwa kolejne `check.ps1` zostawiają `git status` czysty i identyczne osiem PNG.
- Żaden skrypt nie instaluje globalnie ani nie zmienia systemowego `PATH`.
- README i RUNBOOK wymieniają dokładne komendy oraz layout katalogów na `D:`.
