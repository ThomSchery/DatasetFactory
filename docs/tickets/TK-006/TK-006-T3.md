# TK-006-T3 — Validator COCO, realny Tesseract i zapis zależności

Status: WYKONANY

## Cel

Zamienić ręczne asercje struktury eksportu na dowód z prawdziwego validatora,
dołożyć jedyny test dotykający realnego Tesseracta oraz domknąć zapis auditu
i licencji po stronie backendu.

## Zależności

TK-006-T1 (bramka), TK-006-T2 (pełna ścieżka review daje dane wejściowe:
eksport z odrzuconymi i ponownie otwartymi klatkami oraz ręcznymi boksami).

## Zakres / poza zakresem

W zakresie: walidacja wyeksportowanego datasetu prawdziwym validatorem COCO,
integracyjny test realnego Tesseracta, `pip-audit` i tabela licencji backendu.

Poza zakresem: zmiana formatu eksportu, train/val, YOLO, poprawianie jakości
OCR (TD-004/TD-014 zostają otwarte), packaged-local i decyzja o dystrybucji
binarki (T4).

## Pliki

- `backend/tests/test_coco_export.py` oraz nowy test validatora
- nowy test integracyjny Tesseracta
- `pyproject.toml` — wyłącznie jeśli validator wymaga dev dependency
- `docs/tickets/TK-006/log.md`, `docs/TECH_DEBT.md`

## Kontrakt

1. Wyeksportowany dataset jest otwierany przez prawdziwy validator COCO, nie
   przez własną interpretację schematu. Jeśli wymaga to nowej dev dependency,
   obowiązuje procedura pakietowa projektu: stabilna wersja, oficjalne
   repozytorium, lockfile, audit i licencja odnotowane w logu. Bez beta/RC.
2. Eksport zawiera wyłącznie zaakceptowane klatki i ich anotacje. Klatka
   odrzucona, klatka ponownie otwarta i niezaakceptowana oraz anotacja usunięta
   nie mogą się w nim pojawić. Liczniki źródeł w manifeście muszą się zgadzać
   z faktyczną liczbą anotacji OCR i ręcznych.
3. Test integracyjny uruchamia realny Tesseract, gdy zależność jest dostępna
   pod ścieżką z konfiguracji i zgadza się jej SHA-256. Gdy jej nie ma, test
   jest jawnie pominięty z podaną przyczyną — nigdy cicho zielony.
4. `pip-audit` jest już dev dependency; jego wynik oraz licencje zależności
   backendu trafiają do logu, tak jak zrobiono to dla frontendu w FE-001.

## Logika

Realny Tesseract jest w projekcie oznaczony jako `experimental` z
`quality_gate=failed` (TD-014), więc ten test dowodzi integracji adaptera —
timeoutu, provenance i ścieżki błędu — a nie trafności rozpoznawania. Nie
dopisuj asercji na jakość odczytu; to nie jest cel tego ticketu i nie zmieni
statusu TD-004.

## Done Criteria

- Prawdziwy validator COCO otwiera wyeksportowany dataset i przechodzi.
- Test dowodzi, że eksport nie zawiera klatek odrzuconych, ponownie otwartych
  bez akceptacji ani usuniętych anotacji, a liczniki manifestu się zgadzają.
- Test realnego Tesseracta przechodzi na hoście z zależnością i jest jawnie
  pominięty z przyczyną tam, gdzie jej nie ma.
- `pip-audit` bez znanych wysokich podatności; wynik i licencje backendu
  zapisane w logu; brak wersji beta/RC.
- `check.ps1` przechodzi w całości; `git status` czysty.
